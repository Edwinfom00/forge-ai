# ForgeAI — Design System

## Design Mandate

**This is not a generic SaaS dashboard.**

ForgeAI is the operating system for AI software engineering. Its UI must look like it was built by the best design team in the world in 2026 — not generated by an AI in 2 minutes.

Every screen must pass the AI slop test: if someone can look at it and immediately say "AI made that", it has failed.

## 2026 Design Direction

### The Scene

A senior engineer opens ForgeAI at 11pm on a 32" 4K monitor in a dark studio. They are running three terminal panes alongside it. The tool must feel like it belongs in that environment — precise, powerful, fast, and visually extraordinary.

### Color Strategy: **Committed Dark**

ForgeAI is a dark-mode-first product. Not dark "because tools look cool dark" — dark because:
- Engineers live in dark terminals, dark IDEs, dark environments
- The graph visualization and code output read far better on dark surfaces
- The brand signal is precision and power, not approachability

**Primary palette (OKLCH):**

```css
/* Base — near-black with a cold blue-violet tint. Not pure black — that's void, not craft. */
--color-bg:           oklch(0.09 0.012 260);
--color-surface:      oklch(0.13 0.010 260);
--color-surface-raised: oklch(0.17 0.009 260);
--color-border:       oklch(0.26 0.008 260);
--color-border-subtle: oklch(0.19 0.007 260);

/* Ink — blue-tinted whites, never pure #fff */
--color-ink:          oklch(0.97 0.006 260);
--color-ink-muted:    oklch(0.65 0.012 260);
--color-ink-subtle:   oklch(0.42 0.010 260);

/* Brand accent — electric indigo. Not purple, not blue. The exact hue of compiled intelligence. */
--color-accent:       oklch(0.68 0.22 285);
--color-accent-dim:   oklch(0.58 0.18 285);
--color-accent-glow:  oklch(0.68 0.22 285 / 0.15);

/* Semantic */
--color-success:      oklch(0.72 0.16 145);
--color-warning:      oklch(0.78 0.18 75);
--color-error:        oklch(0.65 0.20 25);
--color-info:         oklch(0.70 0.14 220);

/* Graph node colors (for org/workflow visualization) */
--color-node-dept:    oklch(0.62 0.16 250);
--color-node-team:    oklch(0.65 0.14 195);
--color-node-agent:   oklch(0.70 0.18 285);
--color-node-tool:    oklch(0.68 0.14 150);
```

**Absolute color bans:**
- No warm/cream/sand/beige backgrounds (`oklch L 0.84-0.97, C < 0.06, hue 40-100`) — this is the AI default of 2026
- No navy-and-gold fintech palette
- No SaaS teal-and-purple gradient duos
- No gradient text (`background-clip: text`) — ever
- No glassmorphism unless purposeful and rare

### Typography

**Font pairing:**
- **Display / Headings:** `Inter` var — tight tracking at display sizes only
- **Monospace / Code / FIR output / IDs:** `JetBrains Mono` — already loaded in the app
- **UI labels / body:** `Inter` regular — never system-ui (inconsistent rendering)

**Rules:**
- Display heading letter-spacing: no tighter than `-0.03em`. Current AI default of `-0.05em` to `-0.085em` makes letters touch. Floor is `-0.04em`.
- Body line length: max `68ch`
- `text-wrap: balance` on H1–H3
- Hero headings: clamp max `5rem` — above that is shouting
- Don't use small-caps tracked eyebrows ("ABOUT", "FEATURES", "PRICING") on every section — this is 2023 AI grammar
- Don't use numbered section markers (`01 / 02 / 03`) as default scaffolding

### Layout & Spacing

- Use CSS Grid for 2D layouts, Flexbox for 1D — don't default Grid when `flex-wrap` works
- Vary spacing for rhythm — not uniform `gap-4` everywhere
- No nested cards — ever
- Cards: max `border-radius: 10px` — `24px+` on cards is the AI tell
- No identical card grids repeated endlessly (icon + heading + body × 6)
- Build a semantic z-index scale. No `z-index: 9999`

### Motion

- Motion is part of the design, not an afterthought
- Ease curves: `ease-out-quart` / `ease-out-expo` — no bounce, no elastic
- Compiler stage transitions: staggered progress, subtle glow pulses on active stage
- Graph edges: animate on render (draw-on effect with `stroke-dashoffset`)
- Agent nodes: entrance with fade + slight upward translate, staggered per-node
- `@media (prefers-reduced-motion: reduce)` on every animation — non-optional
- No reveal animations that gate content visibility (content must be visible even if JS fails)

### Interaction

- Dropdowns: use native `<dialog>` / popover API or `position: fixed` — never `position: absolute` inside `overflow: hidden`
- Focus rings: visible, branded (accent color outline), never removed
- Hover states: subtle `background-color` shift — not border-only or shadow-only
- Loading states: skeleton loaders that match the shape of the real content, not spinners

## Surface-by-Surface Design Decisions

### Compiler Surface (Primary Hero)

The compiler is the product. Its design must be extraordinary.

- **Input area:** Large, focused textarea with character count, keyboard shortcut hint (`⌘↵ to compile`). Generous padding. Monospace font optional toggle.
- **Compilation progress:** Real-time stage ticker — 12 stages, each with an icon, name, and elapsed time. Subtle accent glow on the active stage. Lines animate in as they complete.
- **FIR output panel:** Split-pane layout. Left: compiled org tree. Right: raw JSON/YAML with syntax highlighting. Toggle between views.
- **Export bar:** Sticky bottom bar with target runtime icons. Click to export. Loading state with artifact download.

### Graph Visualization (Key Differentiator)

- Dark canvas (`oklch(0.07 0.010 260)`) — slightly darker than the app surface
- Nodes: pill-shaped with role icon + name. Color-coded by type (dept/team/agent/tool).
- Edges: curved Bezier with animated dash on hover. Accent-colored for critical paths.
- Minimap: always visible, bottom-right corner
- No decorative illustrations in the canvas — only the graph itself

### Dashboard

- Two-column layout: main content left, quick actions / recent activity right
- Stats: raw numbers in `JetBrains Mono`, no `border-left` stripe accents
- Recent compilations: a clean list, not a card grid. Show project name, status badge, time elapsed, target runtime icon.
- Empty state: not a mascot illustration. A centered prompt: "Compile your first AI organization →" with a keyboard shortcut hint.

### Navigation (Sidebar)

- Width: `240px` collapsed content
- Items: icon + label. Active item: accent background at 15% opacity + full-opacity label + left accent bar (1px, not 4px)
- Groups: subtle label separator, not bold headers
- Bottom: user avatar + name + settings icon. No elaborate user card.

## Absolute Design Bans for ForgeAI

In addition to the impeccable skill's bans:

- No hero-metric template (big number + small label + gradient accent) — this is the SaaS dashboard cliché
- No hand-drawn / sketchy SVG illustrations
- No `repeating-linear-gradient` stripe backgrounds
- No `border: 1px solid X` + `box-shadow: 0 Npx Mpx` on the same element (the ghost-card pattern)
- No `border-left: 4px solid accent` as a card or callout accent
- No marketing-style sections inside the app UI — feature cards, pricing-style layouts, testimonials
- No stock iconography (flat colorful icons) — use Lucide React only, monochrome

## The Quality Bar

Every interface must meet this bar before shipping:

1. **Contrast** — body text ≥ 4.5:1, large text ≥ 3:1. Check every gray-on-dark combination.
2. **Responsive** — test at 1280px, 1440px, and 1920px. No horizontal overflow.
3. **Empty states** — every list, table, and panel has a designed empty state.
4. **Loading states** — every async operation has a skeleton or progress indicator.
5. **Error states** — every form and data fetch has a typed error display.
6. **Focus rings** — visible on every interactive element. Test with keyboard-only navigation.
7. **Motion** — every animation has a `prefers-reduced-motion` alternative.
8. **AI slop test** — would a senior designer at Linear, Vercel, or Anthropic be proud of this? If not, rework.
